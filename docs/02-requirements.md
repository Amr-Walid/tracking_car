# 02 - المتطلبات الكاملة للنظام (Requirements / PRD)

> اسم مقترح للمشروع: **Fleet Pulse** (تقدر تغيره). الملف ده بيحدد "إحنا عاوزين إيه بالظبط" قبل ما نكتب سطر كود.

---

## 1. المشكلة (Problem Statement)

1. المتابعة **يدوية**: المدير لازم يفتح كل سواق لوحده.
2. **مفيش تنبيه لحظي** لما سواق يقف فترة طويلة.
3. التقارير **متأخرة** (ساعتين) والمشكلة بتتكشف بعد **3-4 أيام**.
4. السواقين بيتحركوا في **أماكن مفيهاش شبكة** والبيانات بتضيع أو بتتلخبط.
5. مفيش **حضور وانصراف** مربوط بالموقع.
6. مفيش **تحليلات** تساعد على اتخاذ قرار.

## 2. الهدف (Goals)

- اكتشاف أي وقوف غير طبيعي خلال **30 دقيقة** (قابل للتعديل) وإرسال إشعار **فوراً**.
- **صفر فقد في البيانات** حتى لو النت قاطع ساعات.
- Dashboard واحد يوريك **كل السواقين في نظرة واحدة**.
- تقرير يومي آلي يوصلك الصبح بكل مخالفات امبارح.
- السواق **ميتعاملش مع التطبيق** غير في الحضور والانصراف.

## 3. المستخدمين (Personas)

| الدور | بيعمل إيه |
|---|---|
| **السواق (Driver)** | يسجل حضور/انصراف بس. التطبيق يشتغل لوحده في الخلفية |
| **المشرف (Supervisor/Dispatcher)** | يتابع الخريطة الحية، يستقبل التنبيهات، يتصل بالسواق، يقفل التنبيه بسبب |
| **المدير (Manager)** | تقارير، تحليلات، KPI، مقارنة السواقين |
| **الأدمن (Admin)** | إضافة سواقين/أجهزة، ضبط القواعد والـ Geofences والورديات والصلاحيات |

## 4. المتطلبات الوظيفية (Functional Requirements)

### 4.1 تطبيق السواق (Driver App - Android أساساً)

| ID | المتطلب | الأولوية |
|---|---|---|
| D-01 | تسجيل دخول مرة واحدة بس (رقم موبايل + OTP أو كود من الأدمن) وربط الجهاز بالسواق (Device binding) | Must |
| D-02 | زرار **تسجيل حضور (Check-in)**: يسجل الوقت + الموقع + (اختياري) سيلفي | Must |
| D-03 | زرار **تسجيل انصراف (Check-out)** | Must |
| D-04 | بمجرد الحضور، التتبع يبدأ تلقائياً في الخلفية (Foreground Service) | Must |
| D-05 | التتبع يكمل حتى لو التطبيق اتقفل من الـ Recent أو الموبايل عمل Restart | Must |
| D-06 | **تخزين أوفلاين** لكل نقطة في قاعدة بيانات محلية (SQLite) قبل أي محاولة رفع | Must |
| D-07 | رفع تلقائي على دفعات (Batch) لما النت يرجع، بالترتيب، بدون تكرار | Must |
| D-08 | إرسال **Heartbeat** كل 5 دقايق (حالة البطارية، GPS شغال؟، النت، نسخة التطبيق) | Must |
| D-09 | اكتشاف وإبلاغ: GPS اتقفل، صلاحية الموقع اتسحبت، Battery saver، Mock/Fake GPS، وضع الطيران | Must |
| D-10 | السواق **مايقدرش يوقف التتبع** أثناء الوردية (مفيش زرار Pause) | Must |
| D-11 | إشعار ثابت (Persistent notification) "الوردية شغالة" — ده إجباري من Android | Must |
| D-12 | Onboarding wizard يساعد السواق يدي الصلاحيات ويقفل Battery optimization حسب ماركة الموبايل (Xiaomi/Oppo/Samsung...) | Must |
| D-13 | زرار SOS (اختياري) | Should |
| D-14 | التتبع يقف تلقائياً بعد الانصراف أو نهاية الوردية + مهلة (خصوصية) | Must |
| D-15 | تتبع ذكي حسب الحركة لتوفير البطارية | Must |
| D-16 | تحديث إعدادات التتبع من السيرفر (Remote config) بدون تحديث التطبيق | Should |
| D-17 | إدخال سبب الوقوف من السواق لما السيستم يسأله (اختياري: "أنا عند عميل/بنزينة/عطل") | Could |

### 4.2 السيرفر (Backend)

| ID | المتطلب | الأولوية |
|---|---|---|
| B-01 | API لاستقبال نقط الموقع على دفعات مع **Idempotency** (نفس النقطة متتسجلش مرتين) | Must |
| B-02 | ترتيب النقط حسب **وقت التسجيل على الموبايل** مش وقت الوصول للسيرفر | Must |
| B-03 | **Stop detection** لحظي (Real-time) | Must |
| B-04 | **Alert Engine** بقواعد قابلة للتعديل | Must |
| B-05 | إرسال الإشعارات: Push (FCM) + Telegram/WhatsApp + داخل الداشبورد | Must |
| B-06 | **Watchdog**: لو جهاز سواق في وردية مبعتش أي حاجة X دقيقة → تنبيه "انقطاع اتصال" | Must |
| B-07 | إعادة حساب الرحلات والوقفات لما بيانات أوفلاين قديمة توصل (Backfill reprocessing) | Must |
| B-08 | بث لحظي للداشبورد (WebSocket) | Must |
| B-09 | Jobs ليلية: التقرير اليومي + KPI | Must |
| B-10 | Reverse geocoding (تحويل الإحداثيات لعنوان) مع Cache | Should |
| B-11 | Map matching (تنعيم المسار على الطرق) | Could |
| B-12 | Audit log لكل عمليات المشرفين | Should |

### 4.3 لوحة التحكم (Web Dashboard)

| ID | المتطلب | الأولوية |
|---|---|---|
| W-01 | **خريطة حية** لكل السواقين بألوان الحالة + فلترة (فرع/مجموعة/حالة) | Must |
| W-02 | **مركز التنبيهات (Alert Center)**: قائمة لحظية + صوت + Acknowledge + سبب الإغلاق | Must |
| W-03 | **Timeline يومي** لكل سواق (رحلة → وقفة → رحلة...) | Must |
| W-04 | **Replay**: إعادة تشغيل خط السير بسرعة متغيرة | Must |
| W-05 | إدارة Geofences (رسم دايرة/مضلع) + نوعها + قواعدها | Must |
| W-06 | إدارة السواقين، الأجهزة، الورديات، المجموعات | Must |
| W-07 | التقارير والتحليلات (تفاصيلها في ملف 05) + تصدير Excel/PDF | Must |
| W-08 | ضبط قواعد التنبيه (مدة الوقوف، السرعة، ساعات العمل...) | Must |
| W-09 | صلاحيات (RBAC): مشرف يشوف فرعه بس | Should |
| W-10 | واجهة عربي (RTL) + إنجليزي | Must |
| W-11 | تطبيق موبايل للمشرف (أو PWA) لاستقبال التنبيهات | Should |

## 5. قواعد التنبيهات المطلوبة (Alert Rules) — القلب بتاع النظام

| # | التنبيه | الشرط الافتراضي (قابل للتعديل) | الخطورة |
|---|---|---|---|
| A1 | **وقوف طويل (Prolonged Stop)** | السواق واقف في نطاق 150م لمدة ≥ **30 دقيقة** وهو في الوردية وخارج مكان مسموح | عالية |
| A2 | وقوف طويل جداً (تصعيد) | نفس الوقفة وصلت 60 دقيقة → يتبعت للمدير | حرجة |
| A3 | **انقطاع الاتصال** | مفيش أي Heartbeat/نقطة لمدة **15 دقيقة** وهو في الوردية | متوسطة |
| A4 | الجهاز بيبعت بس **GPS مقفول** | Heartbeat فيه gps_enabled=false | عالية |
| A5 | **Fake GPS** | isMock=true أو قفزات مستحيلة (سرعة > 200 كم/س بين نقطتين) | حرجة |
| A6 | بطارية ضعيفة | < 15% | منخفضة |
| A7 | الموبايل اتقفل | آخر Heartbeat فيه shutdown event أو انقطاع مع بطارية كانت قليلة | متوسطة |
| A8 | سرعة زيادة | > 100 كم/س لمدة > 60 ثانية (أو حسب نوع الطريق) | متوسطة |
| A9 | خروج من منطقة العمل | خرج من Geofence "منطقة التشغيل" | عالية |
| A10 | دخول منطقة ممنوعة | دخل Geofence نوع "ممنوع" | عالية |
| A11 | تأخير في الحضور | محضرش بعد بداية الوردية بـ 15 دقيقة | منخفضة |
| A12 | حركة بعد الانصراف/خارج الوردية | (لو العربية بتاعة الشركة) | متوسطة |
| A13 | زيارة غير منتهية | دخل عند عميل وقعد أكتر من المسموح لنوع العميل | متوسطة |
| A14 | صلاحية الموقع اتسحبت / التطبيق اتمسح | حدث من الجهاز أو انقطاع نهائي | حرجة |

**ملحوظة مهمة عن التنبيه الأوفلاين:** لو السواق واقف 30 دقيقة **في مكان مفيهوش شبكة**، الموبايل نفسه مش هيقدر يبعت. الحل (تفاصيله في ملف 04):
1. السيرفر هيطلع تنبيه **A3 (انقطاع اتصال)** بعد 15 دقيقة.
2. الموبايل بيحسب الوقوف **محلياً** وأول ما يلقط أي شبكة (حتى ضعيفة) يبعت **حدث الوقوف أولاً** (أولوية) قبل باقي النقط.
3. لما البيانات توصل، التنبيه A1 يتسجل **بأثر رجعي** بالوقت الحقيقي (مثلاً: "وقف من 10:05 لـ 11:20 - اتكشف 11:40").
4. (اختياري) **SMS fallback**: لو مفيش داتا بس فيه شبكة موبايل عادية، يتبعت SMS فيه الحدث مضغوط.

## 6. المتطلبات غير الوظيفية (Non-Functional)

| البند | المستهدف |
|---|---|
| زمن التنبيه | أقل من **60 ثانية** من لحظة تحقق الشرط (لو فيه نت) |
| ظهور الموقع على الخريطة | أقل من 30 ثانية (وهو بيتحرك) |
| فقد البيانات | **0%** (التخزين المحلي يستحمل 7 أيام أوفلاين على الأقل) |
| استهلاك البطارية | أقل من **5-8% في الساعة** أثناء الحركة، أقل من 1% في الساعة واقف |
| استهلاك الداتا | أقل من **30-50 ميجا في الشهر** للسواق |
| دقة المكان | < 20 متر في الحركة على الطرق المفتوحة |
| التوفر | 99.5% للسيرفر |
| التوسع | يدعم 50 → 1000 سواق بدون إعادة تصميم |
| الأمان | HTTPS، JWT، تشفير قاعدة البيانات المحلية، صلاحيات |
| القانون | متوافق مع **قانون حماية البيانات الشخصية المصري 151/2020** ولائحته التنفيذية (ملف 07) |

## 7. خارج النطاق في المرحلة الأولى (Out of scope v1)
- iPhone (هنبدأ Android لأن أغلب السواقين Android، وأندرويد بيدي تحكم أكبر في الخلفية) — هيتعمل في مرحلة لاحقة.
- Crash detection.
- Route optimization / توزيع المهام.
- ربط بأجهزة GPS للعربيات (ممكن مستقبلاً).
