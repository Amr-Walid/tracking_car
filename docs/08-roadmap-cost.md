## 1. المراحل (Roadmap)

### المرحلة 0 — تجهيز (أسبوع 1)
- اختيار Stack نهائي (Native Kotlin vs Flutter+Transistorsoft).
- اختيار موديل موبايل (لو موبايلات شركة) واختباره بـ DontKillMyApp Benchmark.
- السياسة القانونية + نموذج موافقة السواق.
- سيرفر (VPS داخل مصر أو cloud بترخيص).

### المرحلة 1 — MVP (أسابيع 2-7) 🎯 **يحل مشكلتك الأساسية**
| تطبيق السواق | السيرفر | الداشبورد |
|---|---|---|
| Login + device binding | Ingestion API (batch + idempotent) | خريطة حية + ألوان الحالة |
| Check-in / Check-out (أوفلاين كمان) | Stop detection لحظي | جدول السواقين مرتب بالمشاكل |
| Foreground tracking + motion state machine | Alert engine: **وقوف 30 د**، انقطاع، GPS off، mock، بطارية | مركز التنبيهات + Ack + سبب |
| SQLite outbox + sync + priority | Watchdog + FCM wake-up | Timeline + Replay لليوم |
| Heartbeat + integrity checks | **Telegram bot** للتنبيهات | Geofences (مخزن/عميل/ممنوع) |
| Onboarding wizard للصلاحيات | التقرير اليومي (Email/Telegram) | إدارة سواقين/ورديات |

**Pilot:** 10-15 سواق لمدة أسبوعين على ماركات مختلفة → قياس % البيانات الواصلة والبطارية والـ False positives → ضبط الـ thresholds.

### المرحلة 2 — التحليلات (أسابيع 8-11)
- KPIs + Driver Score + daily stats.
- كل التقارير + تصدير Excel/PDF.
- Heatmaps، hotspots، مقارنات، تكلفة الهدر.
- تطبيق/PWA للمشرف + Push.
- RBAC للفروع + Audit log.
- استيراد العملاء كـ geofences.

### المرحلة 3 — متقدم (أسابيع 12+)
- iOS.
- SMS fallback، WhatsApp للمديرين.
- Map matching (OSRM) + مقارنة المسار بأقصر طريق.
- Anomaly detection.
- مهام/زيارات مخططة + Route deviation.
- ربط مع GPS tracker للعربيات / مع نظام HR/Payroll.

## 4. المخاطر وطرق التعامل

| الخطر | الاحتمال | التأثير | الحل |
|---|---|---|---|
| الموبايلات (Xiaomi/Oppo...) بتقتل التطبيق | عالي | عالي | Wizard لكل ماركة + WorkManager watchdog + FCM wake + **موبايلات شركة موحدة + MDM** |
| استهلاك البطارية والسواقين يشتكوا | متوسط | متوسط | Motion state machine + شاحن عربية إجباري |
| False positives (زحمة، عند عميل) تزعج المشرفين | عالي في البداية | متوسط | Geofences للعملاء + أسباب الإغلاق + ضبط الـ thresholds من الـ Pilot |
| التلاعب (Fake GPS، قفل الموبايل) | متوسط | عالي | Integrity checks + تنبيهات + لائحة جزاءات + MDM |
| مناطق بدون شبكة | مؤكد | متوسط | Offline-first + priority sync + SMS fallback + تنبيه انقطاع |
| رفض Google Play | متوسط | منخفض | توزيع داخلي/MDM |
| قانوني (PDPL) | — | عالي | ملف 07 + استضافة محلية + موافقات |
| مقاومة السواقين | متوسط | متوسط | شفافية، تتبع في الوردية بس، ربط بحوافز (Score عالي = مكافأة) |

## 5. مؤشرات نجاح المشروع
- ≥ **98%** من وقت الورديات متغطي ببيانات (بعد الـ sync).
- زمن التنبيه بالوقوف ≤ **31 دقيقة** من بداية الوقفة (لو فيه نت).
- انخفاض **الوقت الضائع** 30-50% خلال أول 3 شهور (المعتاد بعد تطبيق أنظمة المتابعة).
- المشرف بيقضي **< 30 دقيقة/يوم** في المتابعة بدل ساعات.
- اكتشاف المشاكل **في نفس اليوم** بدل 3-4 أيام.
